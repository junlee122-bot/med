# HelixForge AI — 심사위원 Q&A 방어 시트

> 본 시스템은 연구 의사결정 보조 도구이며, 전문가의 과학적·임상적·규제적·윤리적 검토를 대체하지 않습니다. 최종 판단과 책임은 연구자에게 있습니다.

**Q1. 이 시스템은 챗봇과 무엇이 다른가?**
A. 실제 도구 어댑터, 감사 로그, 검증, 자기수정을 갖춘 멀티에이전트 워크플로우입니다. (Agent Cockpit에서 확인)

**Q2. 실제 데이터는 무엇을 사용했는가?**
A. PubMed·ChEMBL·ClinicalTrials.gov(실시간), RDKit·TDC(로컬). (Evidence Explorer / Tool Registry)

**Q3. 데모 결과가 조작되지 않았다는 근거는?**
A. 모든 출력에 출처 유형이 표기되고, 소스 거버넌스가 오분류를 차단합니다. (Source-Type 감사)

**Q4. 기록/재생은 왜 fake가 아닌가?**
A. 이전에 실제로 수집한 실행을 재생하며 `RECORDED_REAL_TOOL_OUTPUT`로 명확히 표기합니다. (Snapshots)

**Q5. 분자 후보가 실제 신약 후보인가?**
A. 아닙니다. 전문가 검토용 in-silico 후보 우선순위화이며 습식/임상 검증을 주장하지 않습니다.

**Q6. 습식 실험 없이 과학적 타당성을 어떻게 주장하는가?**
A. 회고적 재발견({f['retro']}/5), 근거 연결, RDKit 검증, assay/다양성 분석으로 제한적 타당성만 제시합니다.

**Q7. RDKit/TDC/ChEMBL 결과는 어떻게 검증했는가?**
A. RDKit 유효성·디스크립터, ChEMBL 실제 ID, TDC 실제 split을 사용하며 근거 QA로 점검합니다.

**Q8. Vina/REINVENT4 미실행이면 분야 2가 약한 것 아닌가?**
A. 정직하게 `CONFIGURED_BUT_NOT_RUN`으로 표기하고, ChEMBL 실제 구조 + RDKit 검증으로 분야 2를 실증합니다.

**Q9. 규제 대응이 heuristic이면 분야 3이 약한 것 아닌가?**
A. 휴리스틱임을 명시하고, 로컬 문서 보조 모드와 RAG 계획을 제시합니다. 공식 규제 준수는 주장하지 않습니다.

**Q10. 안전성 위험은 어떻게 막는가?**
A. 합성 경로·용량·의료 자문 미제공, 한/영 안전 린트, 소스 거버넌스, 안전 게이트로 차단합니다.

**Q11. 한/영 보고서의 과장 표현은 어떻게 막는가?**
A. 한국어·영어 과장 패턴을 탐지·재작성하고, 위반 시 내보내기를 차단/검토요구합니다.

**Q12. API가 본선 당일 실패하면?**
A. 기록 재생(offline replay)으로 실제 데이터를 시연합니다. 실시간 실패는 부분 결과로 허용됩니다.

**Q13. 리소스 효율성은 어떻게 증명하는가?**
A. 로컬 결정론적 도구 + 캐시/재생, 부분 실패 허용, LLM 토큰 비용 없음. (Impact / Resource 지표)

**Q14. 실제 사업화 가능성은?**
A. 학계 랩·제약 초기탐색팀·중개연구그룹의 탐색/문서화 부담 절감. 인간 검토는 필수 유지.

**Q15. 한계는 무엇인가?**
A. 습식/임상/규제 검증 없음, Vina 픽스처 한계, REINVENT4 외부 학습, 규제 RAG 계획 단계.

**Q16. 향후 개발 우선순위는?**
A. 생성 루프 실연, ADMET 예측 모델 학습, 규제 문서 RAG, UniProt/PubChem 정체성 교차검증.
